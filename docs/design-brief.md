# OpenTournament — предложение по дизайну и UX

Статус: направление для согласования, не утверждённый макет и не реализация. Дата: 2026-11-13.

## Основание

Пользователь запросил существующие визуальные альтернативы, включая киберспортивные площадки, и выразил предпочтение содержательному дизайну с упором на UX. Сравнение семи платформ с официальными ссылками — [frontend-reference-research.md](frontend-reference-research.md). Дополнительно непосредственно просмотрены DOM и скриншоты четырёх реальных площадок; закрытые кабинеты и реальные регистрации не проверялись.

## Предлагаемая композиция

1. Небольшая постоянная навигация: «Турниры», «Мои команды», «Мои турниры», «Уведомления». Три игры — быстрый фильтр каталога; мобильная навигация имеет текстовые подписи.
2. Первый экран каталога показывает настоящие соревнования, поиск и фильтры. В строке/небольшой карточке: игра, название, срок регистрации, принято команд, тип сетки и формат серий. Рекламный первый экран не нужен для участия.
3. Шапка турнира содержит название, игру, состояние, дату с часовым поясом, принято/доступно мест и главное действие текущего пользователя.
4. Вкладки турнира: «Обзор», «Команды», «Сетка», «Матчи», «Правила». Действия организатора доступны в контексте его турнира, а не на общей странице метрик.
5. Блок «Мой следующий матч» содержит соперника/ожидание соперника и переход к встрече. Команда пользователя выделяется умеренно, не подменяя результаты других команд.
6. Команда показывается как состав из пяти мест, капитан и приглашения. Недостающее место видно до подачи заявки.
7. Форма создания турнира разделена на короткие смысловые секции: основные сведения; сроки/команды; сетка/серии; предварительный просмотр правил. При ошибке корректные поля сохраняются.

## Визуальное направление — предложение

Графитовый фон, небольшая разница тонов между областями, контрастный основной текст, один холодный акцент для действий. Цвет игры допустим как небольшой маркер, а состояния сопровождаются текстом. Заголовки плотные и выразительные, обычный текст читаемый; цифры счёта стоят ровно. Сдержанные радиусы и границы помогают разделять контент. Точные шрифты, размеры и цвета проверяются на собственном макете, а не выдаются за измеренные стили источника.

В основе — содержимое турнира. Большие декоративные блоки, произвольные KPI, придуманная статистика «игроков онлайн», фоновые сияния и постоянно движущиеся элементы не входят в предложение. Иллюстрации возможны там, где помогают отличить игру или соревнование. Тексты, логотип OpenTournament и композиция собственные; чужие фирменные изображения и CSS в проект не переносятся.

## Сетка на 32 команды

- На большом экране — горизонтальные колонки раундов с читаемыми карточками; страница не уменьшает текст ради размещения всей схемы сразу.
- Double имеет явно подписанные верхнюю и нижнюю ветки; гранд-финал и условный повтор выделены по роли, а не по декоративной яркости.
- «Найти мою команду» и «Мой матч» переводят к нужному месту; понятны направление перехода и источники ещё неизвестных соперников.
- На узком экране — выбор ветки/раунда и вертикальный список встреч, с дополнительным просмотром общей схемы. Это собственное предлагаемое поведение; адаптивность сайтов-источников не тестировалась.
- Пустой соперник обозначается источником: победитель/проигравший конкретной встречи. Условный повтор финала подписан «потребуется при победе команды из нижней сетки».

## UX-проверки

| Ситуация | Требуемая ясность |
| --- | --- |
| В команде четыре человека | До отправки видно «нужен ещё один игрок» и есть переход к приглашениям |
| Заявка подана, но не принята | Статусы явно различаются; пользователь не считает место подтверждённым |
| Набор неполный | Организатор видит точный недобор, запуск недоступен с причиной, предложены продление или отмена |
| Обычные матчи BO3, финал BO5 | Два поля и подпись, к каким встречам относится финал; соответствующий формат виден у каждой встречи |
| Сохранён результат | До отправки виден победитель; после — актуальная сетка; повторное нажатие не создаёт второй эффект |
| Исправление запрещено | Указана сыгранная зависимая встреча, а не необъяснимый отказ |
| Сервис временно недоступен | Ввод сохраняется, есть повтор, неоднозначный исход изменения проверяется без второй заявки |
| У пользователя нет прав | Интерфейс объясняет допустимое действие; сервер всё равно проверяет права |
| Браузер обновлён | Поведение сессии соответствует согласованному P6; этот выбор пока открыт |

Проверяются клавиатурная навигация, видимый фокус, читаемые ошибки полей и различимость состояний без опоры только на цвет. Конкретные контрасты и размеры проверяются на макете; скриншот не доказывает удобство интерфейса.

## Следующий шаг

После согласования направления — небольшая собственная композиция каталога и страницы турнира, проверка сценария капитана и сетки 32 команд. После согласования ТЗ и макета — реализация. Технология frontend выбирается по нужной интерактивности и простоте обучения, а не копируется у источника. Вариант HTML/CSS с модульным JavaScript остаётся кандидатом, не принятым решением.
